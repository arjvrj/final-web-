# Homepage demo video — how it works

A YouTube tutorial sits on the landing page, directly below the hero and above
“How it works”. Everything about it — the video, the title, the description, the
thumbnail, whether it appears at all — is set in the owner panel. Nothing is
hardcoded, and there is no second copy of these rules anywhere.

```
Owner panel → Homepage  (owner_homepage.php)
        │
        │  POST ?action=save   (CSRF + owner only)
        ▼
includes/home_video.php  ── validates, then writes seven rows in `settings`
        │
        ▼
app/home.php  →  rg_home_video_render()  →  the section
```

## 1. What a visitor sees

1. A small **▶ Watch Demo** badge.
2. **See How ReviewAI Works** — “ReviewAI” in the brand purple (#4B20DC).
3. The saved description underneath.
4. A 16:9 player card: thin lavender border, soft shadow, rounded corners, and a
   central purple play button that pulses gently.
5. The saved video title as a caption under the player.
6. **Watch on YouTube ↗** (opens the configured channel or video in a new tab)
   and the note **Quick 2-Minute Tutorial**.

The poster is, in order of preference:

1. the thumbnail the owner uploaded;
2. YouTube's own preview image for that video;
3. a built-in ReviewAI card drawn in CSS — logo, **Complete Setup Guide**,
   **in 2 Minutes**, and a phone mockup of the customer page.

The third one needs no file and no network, so the section can never show a
broken image.

## 2. Nothing loads until the visitor asks

No `<iframe>` ships with the page. Pressing play creates it:

```
https://www.youtube-nocookie.com/embed/VIDEO_ID?autoplay=1&rel=0&modestbranding=1&playsinline=1
```

So the landing page stays fast, YouTube sets no cookie before the click, and
playback happens inside ReviewAI — the visitor is never redirected. The URL is
built in PHP from the validated 11-character id; the browser sends nothing that
could change it.

If the frame has not loaded after nine seconds, the player says so and offers the
same video on YouTube instead of leaving a black rectangle.

## 3. Why the admin cannot break the page

| Risk | What stops it |
|---|---|
| A link to somewhere else | Only youtube.com / youtu.be / youtube-nocookie.com links parse; everything else is refused with a message |
| Pasting an `<iframe>` or embed HTML | The video id is extracted and re-validated; the raw input never reaches the page |
| `javascript:` / `data:` links | Refused by the parser and by `rg_safe_url()` for the channel link |
| A half-saved configuration | Every field is validated before the first write; a bad URL or a blank video with the section switched on writes nothing |
| An empty player on the homepage | The section prints nothing unless it is switched on **and** has a usable video id |
| A deleted thumbnail | Falls back to the YouTube preview, then to the built-in card |
| A thumbnail outside the uploads folder | The path must match `assets/uploads/<file>`; `../` is refused |
| A fake image upload | `getimagesize()` reads the header; the extension comes from the detected type, never from the filename |
| Anyone but the owner | `requireOwner()` runs before any output; the save endpoint is POST + `requireCsrf()` |

## 4. The settings

Stored in the existing `settings` table — no new table, no new admin system:

| Key | Meaning |
|---|---|
| `home_video_enabled` | `1` shows the section, `0` hides it |
| `home_video_url` | the link exactly as the owner pasted it |
| `home_video_id` | the 11-character id, cached from that link |
| `home_video_title` | caption + the frame's accessible name |
| `home_video_description` | the sentence under the heading |
| `home_video_channel_url` | where **Watch on YouTube** goes; empty means the video itself |
| `home_video_thumbnail` | `assets/uploads/…`, or empty for the fallbacks |

The URL is the source of truth: if the cached id and the URL ever disagree, the
id is re-derived from the URL.

## 5. Updating the tutorial

1. Owner panel → **Homepage**.
2. Paste the new YouTube link.
3. Change the title, description or thumbnail if you want to.
4. **Save changes**.

The homepage shows the new video on its next load. There is nothing to redeploy
and no cache to clear. **Preview video** plays the saved video in a modal before
you leave the page.

## 6. Files

| File | What it is |
|---|---|
| `app/includes/home_video.php` | URL parsing, validation, settings, the section markup |
| `app/owner_homepage.php` | the owner page and its save endpoint |
| `app/assets/css/home-video.css` | the section's styles (brand tokens, mobile, reduced motion) |
| `app/assets/js/home-video.js` | click-to-play, poster fallback, load-failure message |
| `app/home.php` | one line calls the section; it is generated by `tools/build-home.mjs` |

## 7. Tests

```
node tools/test-home-video.mjs                       # 78 browser checks
node tools/php-run.mjs tests/php/test_home_video.php \
  --require app/includes/payments.php --require app/includes/ai.php \
  --require app/includes/links.php --require app/includes/functions.php \
  --require app/includes/home_video.php              # 111 PHP checks
```

The browser run proves: the section is the first thing after the hero; the badge,
heading and purple highlight are right; there is **no iframe before the click**;
clicking play creates the YouTube `<iframe>` with the validated embed and
`autoplay=1`; the poster disappears; **Watch on YouTube** has the right href,
`target="_blank"` and `rel="noopener noreferrer"`; a custom thumbnail and channel
are used when saved; the section is absent when switched off, never configured, or
saved with an unusable link; a phone has no horizontal scroll, a ≥56 px play
target and a ≥44 px CTA; reduced motion stops the animations; and every existing
homepage section still renders.

The PHP run proves the parser (every accepted form, every refused one), the embed
URL being built from the id alone, the channel host check, the fallback chain, the
validation-before-write rule, the upload checks (a `.php` renamed to `.png` is
refused) and the exact markup: escaped title, no iframe, both CTA attributes.

What these cannot prove: that YouTube serves your particular video, or that MySQL
stores the rows — this sandbox has neither. Saving on your server and reloading
the homepage is the last check.
